# 运行时

`Runtime2026` 独占一个会话。一次修改操作先保存宿主状态与数据映像，再记录每次远程写入的前值、原保护属性及资源所有权。写入、读取、分配、保护变更和缓存刷新失败会进入逆序恢复。

`Runtime2026` 负责配置投影、注入编排和宿主快照恢复。`ProcessSession2026` 独占进程身份、API 后端和资源操作，执行身份检查、远程读写、逆序恢复及退出清理，不解释宿主布局或用户配置。`ChangeJournal2026` 独占日志记录和事务边界，开始操作时记录边界，提交时构造新日志再替换，撤销时将边界设为零；待恢复记录在恢复成功前不会删除。

| 阶段 | 行为 |
| --- | --- |
| Idle / Active | 可以开始一次串行操作 |
| Applying | 记录操作边界，成功后提交 |
| RollingBack | 逆序恢复本次操作 |
| RecoveryRequired | 保留日志和资源，禁止新修改，允许重试 |

操作结果与会话阶段分开。失败并成功回滚的已连接会话仍为 Active；恢复失败时不能丢弃日志、释放仍被引用的分配区或直接关闭窗口。`undo()` 使用真实修改日志恢复会话开始前的字节，不执行固定撤销字节表。

成功操作按地址区间归并最早前值，句柄、分配区、保护属性和进程变化构成资源边界。失败操作保留逐次前值，不归并。持续轮询和重复应用不会让日志按操作次数无限增长。

原始失败与恢复失败分别使用 `RuntimeFailure2026` 记录操作类型、目标地址、请求长度、实际传输长度和系统错误。API 返回失败时立即读取系统错误；API 返回成功但传输不足时，系统错误为零，避免混入旧错误。部分写入的日志仍保存完整前值，恢复覆盖完整请求范围。阻止新修改时保留两份诊断；恢复重试成功后清除恢复失败，原始失败保留到下一次事务开始。退出清理成功同样清除恢复失败。界面从结构化状态生成失败原因及恢复原因文案，不解释日志或原始宿主字段。主窗口状态区显示摘要，悬停显示完整诊断；提示窗口和每个控件的绑定重复使用，更新不会积累窗口或历史文本。

会话使用 PID、创建时间和进程句柄验证身份。只有已确认身份且句柄发出退出信号，才清理已销毁的地址空间；无法确认身份时保留恢复信息。退出后恢复宿主地址基线，保留最新配置并重新安排待应用项，重连重新识别版本、分配和重定位。

原始注入顺序、宽度和条件分支维护在 `RuntimeInjection2026.cpp`。入口按连接、通用钩子、通知桥、载荷上传、玩法补丁和参数应用划分阶段；已连接的定时器只更新状态动画，参数确认才重新应用参数补丁，游戏通知与游戏对话框关闭触发游戏配置应用。都市、兵法、阵型和地域修正使用明确字段及循环；所有远程修改进入统一事务。游戏快照读取与解码集中在 `GameSnapshots2026.cpp`，不向 GUI 暴露原始地址。

`PatchDescriptor2026` 明确表示 12 字节的目标地址、写入长度和源地址记录，写入时显式区分伴侣虚拟地址与本机指针。`InlinePatch2026` 表示 16 字节的内联补丁记录。版本检查后由种子表初始化钩子描述符，保留正向及反向表的遍历顺序。远程操作失败由底层抛出异常并进入事务恢复，阶段代码不再维护不可达的布尔失败分支。补丁长度和恢复内容以现有字节及会话日志为依据；游戏侧 IDA 数据库与重制版研究文档用于辅助解释控制流。

离线假后端覆盖默认首次注入的 3503 个故障点，以及部分读写、回滚再次失败、重试、关闭恢复、日志归并和生命周期场景。另有结构化快照、配置模型及字节轨迹检查。

当前不暂停游戏线程，不提供崩溃后的持久恢复。回滚不等于游戏执行期间的原子提交，也不能撤销游戏已执行修改代码产生的副作用；真实并发、通知时序和画面仍需实机验收。
