# 运行时

`Runtime2026` 独占一个会话。一次修改操作先保存宿主状态与数据映像，再记录每次远程写入的前值、原保护属性及资源所有权。写入、读取、分配、保护变更和缓存刷新失败会进入逆序恢复。

| 阶段 | 行为 |
| --- | --- |
| Idle / Active | 可以开始一次串行操作 |
| Applying | 记录操作边界，成功后提交 |
| RollingBack | 逆序恢复本次操作 |
| RecoveryRequired | 保留日志和资源，禁止新修改，允许重试 |

操作结果与会话阶段分开。失败并成功回滚的已连接会话仍为 Active；恢复失败时不能丢弃日志、释放仍被引用的分配区或直接关闭窗口。`undo()` 使用真实修改日志恢复会话开始前的字节，不执行固定撤销字节表。

成功操作按地址区间归并最早前值，句柄、分配区、保护属性和进程变化构成资源边界。失败操作保留逐次前值，不归并。持续轮询和重复应用不会让日志按操作次数无限增长。

会话使用 PID、创建时间和进程句柄验证身份。只有已确认身份且句柄发出退出信号，才清理已销毁的地址空间；无法确认身份时保留恢复信息。退出后恢复宿主地址基线，保留最新配置并重新安排待应用项，重连重新识别版本、分配和重定位。

原始注入顺序、宽度和条件分支直接维护在 `RuntimeInjection2026.cpp`。都市、兵法、阵型和地域修正使用明确字段及循环；所有远程修改进入统一事务。游戏快照读取与解码集中在 `GameSnapshots2026.cpp`，不向 GUI 暴露原始地址。

离线假后端覆盖默认首次注入的 3503 个故障点，以及部分读写、回滚再次失败、重试、关闭恢复、日志归并和生命周期场景。另有结构化快照、配置模型及字节轨迹检查。

当前不暂停游戏线程，不提供崩溃后的持久恢复。回滚不等于游戏执行期间的原子提交，也不能撤销游戏已执行修改代码产生的副作用；真实并发、通知时序和画面仍需实机验收。
