# 架构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 值模型 | `src/model/` | 配置解析、校验、编码、快照和重定位 |
| 运行时核心 | `src/runtime/` | 进程会话、注入、恢复、游戏事件及数据快照 |
| 应用服务 | `src/app/application/` | 期望配置、来源、配置文件加载与安全导出、结构化诊断、提交命令和恢复期间的输入队列 |
| 页面与绑定 | `src/app/ui/` | 编辑草稿、字段绑定、搜索、选择、确认与取消 |
| Win32 后端 | `src/app/platform/` | 窗口、控件、消息、布局、菜单、提示、文件选择、图标与 DPI |

GUI 使用 Windows 原生控件，不包含 Direct 绘制。页面通过封装操作控件，不直接创建窗口、发送控件消息或解释游戏内存。状态文案位于 `RuntimeStatusText.cpp`，核心只返回结构化状态。

窗口在初始化完成后显示；控件位置和分页可见性由后端批量提交，列表通过批量接口预留存储并填充。重绘控制只作用于已显示的列表，作用域结束时恢复，避免误显示隐藏窗口或分页。页面只提供内容，不处理重绘和底层窗口布局 API。

核心独占游戏会话、句柄、注入映像和修改日志。应用层独占用户确认的期望配置与来源，页面通过只读配置视图、具名提交命令和结构化快照交换数据，不能直接修改核心或待应用标记。核心中的编码配置是会话有效投影；默认值回填、游戏快照和会话恢复不会反向覆盖期望配置。游戏通知由前端转交核心状态机。回调 HWND 是注入协议的接收端，核心不会用它更新控件。

核心内部由 `Runtime2026` 编排注入与宿主配置投影，`ProcessSession2026` 管理进程身份、远程操作和资源恢复，`ChangeJournal2026` 管理修改记录、归并与事务边界。会话模块不依赖恢复布局或应用层；原始失败与恢复失败独立记录，应用读取结构化状态，状态文案层负责呈现操作、地址、传输长度和系统错误。

编辑窗口持有草稿，切换条目前保存当前条目，校验失败保留原选择。取消不提交本窗口草稿；子窗口确认独立提交，父窗口取消只丢弃父窗口未确认的参数。提交时按变更配置组更新核心投影，不在轮询或快照读取中全量双向复制配置。Applying、RollingBack 和 RecoveryRequired 期间的新确认只保存在应用输入队列中，恢复成功后再进入核心；参数应用失败保留确认请求，后续轮询重试。核心完成会话撤销或清理退出进程时递增配置周期，应用据此为下一会话重新提交期望输入与来源策略。所有运行时操作保持同步和串行；核心对象不支持多线程并发访问。主窗口关闭前必须成功 `undo()`，失败时保留窗口、核心和日志以便重试。

固定数据集中在 `src/generated/`，手工逻辑集中在 `src/runtime/`。项目名、输出名不带恢复年份；内部带 `2026` 的 ABI 类型和字段布局仍明确对应原始样本。
