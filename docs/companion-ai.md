<a id="terms"></a>
## 术语与难度偏置

| 名称 | 决策层次与作用 |
| --- | --- |
| 群狼战术 | 同一方分兵，多队利用不同主将和兵法组合 |
| 电脑群攻 | 多势力目标偏置，更容易集中进攻玩家，不要求正式联盟 |
| 电脑乱战系数 | 战略专注程度，影响偏离指定对手、另打其他电脑的随机门 |

基础编队和战略工作已有；群攻玩家与伴侣乱战选项未立项。群攻放宽部分方针下的合攻认定，其他出征资格保留。乱战与混乱兵法无关：1～9通常增加分心出兵，0按负责人野心，当前10与0同分支。见[精确公式](optimizations.md#chaos-targets)。若采用玩家偏置或乱战强度，应列为可选难度配置。

<a id="domestic"></a>
## 内政：按钱粮需求安排工作

伴侣降低资金充足时的商业目标，按季节筛选工作，并预测粮食缺口决定开垦，目的是把有限人物投入更需要的工作。它修改AI目标，不直接改变真实商业上限或收益；内政导向方针只绕过财政缩放，巡察读取城市民心上限。

remake已有经营、钱粮门和局部失败继续处理；季节门、目标缩放与预测曲线未立项。若采用需求平衡，建议内置比较收益、人物机会成本和储备缺口，不开放内部预测参数。见[商业、开垦与巡察](optimizations.md#companion-audit-26)。

<a id="search"></a>
## 探索：扩大可用内容，区分信息权限

伴侣跨同势力军团搜索隐藏人物和宝物，发现后的即时登用独立处理，旨在提高人力与内容利用率。玩家根势力另有例外路径，读取隐藏位置属于信息权限选择。

remake已有探索和未发现人物筛选，电脑结算不进入宝物及玩家专属事件；保留现行权限，未采用电脑宝物扩展。地点、人物、费用和发现结果由公共任务校验，不照搬两个政治参数覆盖同一地址的问题。见[探索](optimizations.md#companion-audit-30)、[参数覆盖](optimizations.md#companion-audit-31)。

<a id="targets"></a>
## 进攻目标：从能够支援的前线推进

伴侣分战略目标、机会空城、玩家群攻和普通设施选择目标，再检查来源钱粮、人物、士气、兵量和范围。来源行程门、普通敌设施接壤门均是资格条件，未占领设施后备保留；初始进攻、场上续攻、目标失效后的事后选敌分别决策。

remake已有目标／来源、沿路选敌及后续目标尝试；伴侣行程门、接壤门和性格门尚无采用决定，自研来源放行／批次预编试验撤回不约束它们。候选策略建议内置，玩家偏置另作难度选择。见[目标与续攻](optimizations.md#companion-audit-58)、[性格门槛](optimizations.md#companion-audit-25)。

<a id="sortie"></a>
## 出征编队：分兵、预留主将与覆盖角色

普通出征按兵量和人物分组，再按主将容量分配；反击另按可用兵及人数编队，预留后续主将，并分散智力角色、考虑相性。角色配额有助于避免辅助能力集中在一队；单人后备偏向保留强将，但实际存在遇不合格者提前返回的行为。

remake已有基础分兵、选将和装备；伴侣分组与配额未立项，与自研批次预编和实际批次优势门分别判断。若采用，建议内置主将预留、角色分配及容量／人物互斥／守备校验，不只提高队数上限，也不开放内部配额。见[普通分兵](optimizations.md#sortie-allocation)、[反击编队](optimizations.md#companion-audit-47)、[单人后备](optimizations.md#companion-audit-48)。

<a id="equipment"></a>
## 兵法、阵型与地形：让配置服务于队伍角色

伴侣从人物兵法生成候选，按费用、可用性和路线过滤，联合调整阵型与物理兵法；智力兵法另有能力分档、智武差概率、去重和后备，进攻与反击顺序不同。三处水路判断用实际地形替代港口类型，禁箭岚还影响局部船型偏好，不代表禁用斗舰。

remake已有选阵、兵法和路径检查，AI仍有港口条件，临水替代及重配策略未完成。建议按合法且付得起的队伍方案内置适配，不随机授予无权限蛮族阵型，不增加阵型优先表调参。见[兵法选择](optimizations.md#companion-audit-49)、[选阵与临水](optimizations.md#companion-audit-51)、[船型分支](optimizations.md#companion-audit-52)。

<a id="defense"></a>
## 预警与反击：按实际威胁保留守军

伴侣用来袭到达时间、普攻和兵法威胁估计留守量，再决定出队兵力；预警读取周边敌对城市风险，不读取玩家未来中继命令。据点类型、孤立及受压情况分别处理，旧帮助的单一留兵数不能推广到全部路径。

remake已有来袭、留兵及确定拒绝后的继续尝试；完整威胁估计未立项，防御资格调整不采用。候选估计建议内置，分开驻兵、伤兵、在途援军和外出兵力；降低反击门槛另作未立项的可选难度项。见[反击留守](optimizations.md#companion-audit-27)、[预警](optimizations.md#companion-audit-29)。

<a id="relay"></a>
## 接力救援：直接无援时向邻城筹兵

目标A缺兵且无直接来源时，伴侣沿A的邻城表登记中继B，其他来源向B筹兵；没有同时预订B→A，后续援A仍由正常规划决定。B无来源就换同表下一城，不递归多跳。后续扫描发现B缺口已覆盖才给A记冷却，可计在途；冷却只限新建中继，不限制直接救援。

原实现混用压力与筹兵需求、全局仅一个待处理中继，冷却编号读写还有差异；39r按Send成功／在途对象近似，不能视为完整等价。

remake已有直接救援和Group2出队；中继状态未立项。若采用，建议内置，分开威胁、需求、承诺和中继状态，按路线／到达时间选择统一据点ID，经公共派兵命令提交，不开放启停或冷却调参。见[登记](optimizations.md#companion-audit-55)、[派遣与冷却](optimizations.md#companion-audit-56)。

<a id="continuation"></a>
## 续攻与协同：整体止损，协调接战

伴侣聚合同目标进攻量，与驻兵、回归兵和相关野外防守量比较，部分陆上长蛇减半，已交战且少守军时有继续例外；这是风险策略，不是精确战力预测。通过直属军团护卫改阵和等待协调到达，最多等待9日仍不保证同步，原实现还混用真实方针位与规划状态。

remake已有每日方针和出发等待；同目标评估、护卫和同步策略为候选。建议内置态势判断，明确到达时窗、等待成本及独立规划状态，不暴露内部比例，也不重复实现现有进退响应。见[续攻](optimizations.md#companion-audit-58)、[协同](optimizations.md#companion-audit-54)。

<a id="retreat"></a>
## 回撤：保存兵力，避开拥堵据点

伴侣从直属军团据点按路线及预计容量排序，考虑士兵、伤兵和在途兵量；全部不合适则退回服务地，该后备不保证容量安全。部分电脑攻城器械会改长蛇以提高机动。

remake已有返回意图、失效服务地修复及公共入城保护，近城容量排序为候选。建议内置可达性／空位规划，所有后备接受同一校验，无目的地则有界重算；士气基线另作可选规则，不默认新增免费改阵开关。见[回撤选址](optimizations.md#companion-audit-59)。

<a id="transport"></a>
## 运输：在来源余量和前线需求之间调度

伴侣账本综合现兵、伤兵、野外部队、在途输送、前线关系和容量，负数兼编码优先级，不等于精确缺口。配对分邻近／非邻近、强／弱需求等阶段，运量受账目和主将容量约束；原实现可能在命令成功前消费额度，39r的留兵倍率没有完整复刻调度。

remake已有输送及现兵／伤兵／在途容量保护；需求驱动运输与运量改造暂缓。未来若采用，分别表达需求、优先级、容量和承诺，准备后预留，失败释放。见[账本](optimizations.md#companion-audit-45)、[配对与运量](optimizations.md#companion-audit-46)。

<a id="staffing"></a>
## 调将与军团组织：让人、兵、资源服务同一战线

伴侣按驻兵、外出、在途和压力分配人员，特定低兵设施分支用于减少占人；军团按城市攻防邻接组成战区，保留合适旧区并处理飞地。年初／年中全势力调将有作者记录，新增顺序不能据此视为已复刻。

remake已有直属配额、余缺调将、空城借人和分区稳定性修复，完整军团重规划不采用，全势力周期调度未立项。若重新评估，应统一考虑可行动人力、任务、预期兵力和角色，限制低收益往返。见[配额](optimizations.md#companion-audit-28)、[组织](optimizations.md#companion-audit-60)、[低兵设施](optimizations.md#companion-audit-61)。

<a id="office"></a>
## 任官：评价、资格与分配共同决定结果

伴侣区分特殊职位、武官和文官评分，并考虑基础能力、宝物、统智类型、资金和忠诚，再处理占职与候选消费。仅替换排序公式不能复刻整个流程。

remake已修复占职、候选消费及非法撤职，保留原作有效能力和忠诚加分；重评分暂缓。未来调整须同时定义职位需求、现任价值与换职成本，规划不直接撤职。见[评分](optimizations.md#companion-audit-43)、[分配](optimizations.md#companion-audit-44)。

<a id="ransom"></a>
## 赎俘：提高处理吞吐，保留成交条件

作者记录将每月赎俘由1人提高到3人，旨在减少重要人物积压；候选、使者、费用和接受条件仍决定成交，不保证每月赎回三人，也不降低赎金。

remake已有工作35、候选／使者及公共命令；频次差异未立项，若采用建议可选。分别统计尝试、提交和成交，保留外交回应与费用规则。见[估价与频次](optimizations.md#companion-audit-35)。

<a id="implementation"></a>
## 实现方式

按世界／规则快照计算需求、生成候选、分配资源，经公共命令准备与提交；世界变化后有界重算。真实威胁、额外筹兵、容量、已承诺和未提交预留分别保存，冷却与随机状态随会话恢复。具体职责和局中生效点见[实现约定](companion-2026.md#implementation)。

资格、唯一人物、容量和资源守恒由公共规则保证，风险偏好与玩家偏置由策略决定。观察候选淘汰、计划与实际提交差异，长期效果仍须动态验证。回复请求、新局初始化及在建输送的证据边界见[未定位记录](optimizations.md#companion-audit-42)。
